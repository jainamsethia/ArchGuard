Privacy

Short version: your analyses are private to your account, and ArchGuard only reads repositories that are already public.

What is stored

  • Your GitHub numeric account id, login and avatar URL, taken from the read:user scope when you sign in. That is the whole of the GitHub permission ArchGuard asks for: it cannot read your private repositories, and it never acts on your behalf.
  • The URL of each public repository you analyse, and the result of the analysis: scores, module names, file paths and findings.
  • A session, so you stay signed in. It lasts 24 hours by default, and signing out ends it immediately.
  • For a watched repository: the alert threshold you chose, the webhook URL you supplied if any, when it was last checked, and a short description of the last result. The webhook URL is stored as you gave it and is never shown back to you or returned by the API, because it commonly carries a token in its path.
  • Findings you have suppressed, so they stay hidden from your view of that repository and nobody else's.
  • Content hashes of the files in a repository you analysed, which is how a re-scan reuses work it has already done. A hash of a file is not the file.

What is not stored

  • Your repository's source code. It is cloned to a temporary directory outside the database and deleted automatically: the clone is kept briefly after the analysis so the dashboard can read from it, then removed by a sweep about an hour later, or sooner when the disk budget is reached. Nothing copies it anywhere else. What is kept permanently is the measurements — including file paths and the lines a finding points at, but not the file contents.
  • Your GitHub access token. It is used once, at sign-in, to read your account, and then discarded.

How long it is kept

A completed analysis and its findings are kept for 90 days, and then deleted by a nightly sweep along with the job that produced them and the content hashes for any repository nothing refers to any more. Long enough for the trend chart and the run comparison to be worth having, and bounded rather than forever.

Two things deliberately do not expire, because they are settings rather than history: a watched repository — its threshold, its webhook and whether it is paused — and the findings you have chosen to suppress. A watch that vanished because nothing had regressed for three months would stop monitoring at the moment it had been quietly working. Both go when you remove them, and when you delete your account.

An analysis that never finished is never swept, at any age. If a job is stuck, the record of it is what makes that findable.

Who can see it

You. Every endpoint that returns analysis data filters on the signed-in account, and another account asking for your results is told they do not exist. If AI features are enabled on this instance, the findings selected for an explanation are sent to the configured model provider.

One thing does leave on your instruction: if you give a watched repository a webhook URL, ArchGuard makes an outbound HTTPS request to it whenever that repository regresses, carrying the repository name and a description of what changed. The address is checked before it is called and again on every send — HTTPS only, public addresses only, no redirects — so it cannot be pointed at something inside our network.

Watching a repository also means ArchGuard re-clones and re-analyses it on a schedule, without you asking each time, until you pause or remove the watch.

Deleting it

Delete account, in the bar at the top of the dashboard, removes your account and every analysis attached to it: its jobs, runs, findings, suppressions and watched repositories. It takes effect immediately and cannot be undone. Any session still signed in as that account — in another browser, on another machine — stops working at the same moment.
